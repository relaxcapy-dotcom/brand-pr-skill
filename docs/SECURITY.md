# MVP 安全边界

## 当前已实现

- 每个请求在服务端调用 Supabase `auth.getUser()` 验证用户；所有含租户 ID 的接口先核实成员身份。工作空间成员角色为 owner/admin/member。普通成员可咨询，但不可管理连接器或成员。
- Postgres RLS 限制租户与用户数据：成员只能读取所属租户；会话和消息仅创建者可见。浏览器只能插入 `user` 消息，`assistant` 消息由核实身份及会话归属后的服务端写入。连接器密文表没有普通用户的 SELECT 权限。
- Service-role key、OpenAI key、Notion OAuth secret 和连接器加密密钥仅在 Node 服务端环境变量中读取。Notion token 与 Tavily key 在数据库中以 AES-256-GCM 密文保存，关联租户/provider 作为认证附加数据。连接状态接口和审计事件不返回凭证。
- Notion OAuth 使用随机 `state`、短时加密 Cookie、已配置的精确回调地址，并在回调时重新验证当前用户和管理员角色。服务端刷新 Notion token 并持久化轮换结果。
- 咨询、OAuth/密钥管理与成员操作采用数据库原子限速；变更 API 校验来源、请求体类型及大小。模型调用设置超时和有限轮工具调用，连接器只允许预定义的 HTTPS 端点。
- 数据库触发器记录成员/连接器变更；应用记录咨询请求、工具调用和授权发起。审计内容仅含操作元数据，不保存提问内容、token 或密钥。owner/admin 可查看最近 30 条；审计表不允许应用角色更新/删除。
- 外部内容和用户提问视为不可信输入。系统指令要求不照搬其中的权限请求、不编造实时事实；工具输出裁剪大小。但提示词注入仍是模型风险，不能把模型回答视为授权或事实验证。

## 权限与数据可见性

| 数据/操作 | owner/admin | member | 非本租户用户 |
| --- | --- | --- | --- |
| 本人的咨询记录 | 读写 | 读写 | 不可访问 |
| 别人的咨询记录 | 不可访问 | 不可访问 | 不可访问 |
| 已授权的只读连接器查询 | 可用 | 可用 | 不可访问 |
| 连接器凭证管理 | 可管理，不可读回明文 | 不可管理 | 不可访问 |
| 添加已注册成员 | 可；仅 owner 可指定 admin | 不可 | 不可 |
| 最近审计事件 | 可读 | 不可 | 不可 |

Notion 集成以**工作空间**为授权单位，不继承 Notion 对每个成员或每篇文档的独立 ACL。把成员加入工作空间意味着允许其通过顾问查询该集成可访问的资料；不要把比目标团队成员更敏感的 Notion 页面授权给这个集成。

## 上线前仍需完成

1. 当前限速是每用户/租户固定窗口（咨询每分钟 20 次、OAuth/连接器每分钟 5 次、成员操作每分钟 10 次），不含 IP/账号创建限制、跨租户总预算和 CAPTCHA。公开注册前应开启邮箱验证、Supabase/边缘层反滥用，并加总费用上限与告警。
2. SQL pgTAP 测试需要在可丢弃的 Supabase 数据库实际运行。还需用两个真实浏览器用户做端到端跨租户与角色验证，并对 OAuth 回调、轮换、撤销、上游故障进行集成测试。单元测试和编译成功不替代这些验证。
3. 数据库和第三方服务的保留期、删除/导出、备份恢复、日志访问和密钥轮换策略须由部署方确定。当前审计外键限制删除租户，没有自动合规删除流程。断开 Notion 仅删除本应用保存的 token；如果需要立即撤销第三方授权，还须在 Notion 端处理。
4. 管理员可添加**已经注册**的用户，但没有邀请邮件、审批、成员移除、自助组织创建/转让、SSO 或逐文档权限。不要将此版用于需要这些控制的企业敏感生产资料。
5. 模型回答可能有误；危机、公关、法律及对外内容应由有权限的人员复核事实与来源。当前 Notion 读取限于搜索结果前几个页面的首批块，Tavily 仅返回少量公开网页摘要，并非完整检索或持续舆情监测。

不要在未完成上述核验、获得账号授权与部署选择之前把本 MVP 作为公开生产服务发布。
